# 日记（v2 重做）

像人的记忆一样：**会变糊、会淡忘，也会因为被反复想起而留得更久。**

旧版是「每天问一次要不要看日记」；这一版把主动权和遗忘都做成机制：
日记自己会老，看不看由她决定，翻看不续命，只有明确「延长」才留得住。

- 核心逻辑：`src/diary-core.js`（纯函数 + 文件锁存储，不依赖桥接）
- 十二个工具：`src/mcp-diary.js`（MCP stdio 服务，名字 `diary`）
- 每轮模糊视图 + 凌晨结算：`src/bridge.js` 的 `buildDiaryBlock` / `runDiarySettleIfDue`
- 状态文件：`state/diary.json`（`config.json` 的 `diary.file` 可改）；每次落盘把上一版留在 `state/diary.json.bak`
- **面板插件**：`plugins/dsh-diary/`（DSH 设置页里的「日记」，看/搜/谨慎编辑 + 备份恢复，见 §15）
- 相关的另一套东西：每天 23:30 写两份**文件**的日记本，见 `JOURNAL.md`
  （`<数据根>\日记` 与 `<数据根>\日记-私密`）——那是「纸」，本页是「记性」。

---

## 1. 四个栏位

| 栏位 | 说明 | 参与每轮模糊视图 |
|---|---|---|
| 普通 `normal` | 小事小记 | 是 |
| 重要 `important` | 会反复想起的事 | 是 |
| 刻骨铭心 `heart` | 大事，几年都还在 | 是 |
| 搁着 `shelved` | 看到了但决定不打开，附理由 | 否 |
| 回收站 `deleted` | 划掉 / 到期未救回，只标 `deletedAt` | 否 |

一条日记由三部分构成：**正文 + 心情 + 当时想说但没说出口的话**。
后两个由她自己决定写不写——工具参数里是可选的，没写就是 `null`，不补默认值。

## 2. 三档参数

| 档位 | 初始寿命 | 延长一次 | 升档提示 | 降档提示 | 到期提醒频率 |
|---|---|---|---|---|---|
| 普通 | 7 天 | +3 天 | 寿命 > 13 天 | — | 1 天一次 |
| 重要 | 21 天 | +7 天 | 寿命 > 60 天 | 剩余 < 10 天 | 3 天一次 |
| 刻骨铭心 | 90 天 | +30 天 | — | 剩余 < 30 天 | 7 天一次 |

**四条配套规则**

1. 寿命从写下那天算，是**绝对时长**，不跟「最后一次想起」走。
2. 翻看不续命；只有明确调用 `diary_extend` 才加天数。
3. 同一天内不管翻多少次，只算一次延长（`lastExtendedDate`）。
4. 升档降档都按**新档位的初始寿命重新算**（`anchorAt` 重置为当天），不在旧寿命上叠加。

## 3. 注入长什么样

每轮只给模糊视图，**不给正文**。按剩余比例分三档：

| 剩余比例 | 给什么 |
|---|---|
| 超过一半 | 心情 + 短标题（正文第一小句，截 16 字） |
| 两成到一半 | 只给心情；没写心情的给短标题 |
| 不到两成 | 只给心情；没写心情的只剩日期 |

```
【日记·作用域】群聊（调 diary_* 工具时 scope=group；私聊与群聊的记忆互不相通，也不该互相提起）

【日记·模糊印象】你只记得个大概，看不到原文：
【刻骨铭心】10月18日 · 心里有点沉　他说自己失恋过　id=d3
【重要】10月20日 · 有点烦　id=d7
（想看哪条就用 diary_open 展开；不打开就一直是这个样子。展开不算留住。）
```

第一行是**作用域**，每轮都会给：她现在是在群聊还是私聊，写/查时必须带对应的 `scope`。

**模糊检索**：每轮把最近聊天文本和日记关键词比对，命中的条目排到最前面，标题里点出命中词：

```
【日记·模糊印象】聊到「失恋」的时候，这几条忽然冒了出来——你只记得个大概，看不到原文：
```

关键词来自 `diary_write` 的 `keywords`；不填就从正文里粗抽中文**二元组**
（不做分词，但先遮蔽「自己/晚上/那天/其实」这类虚词整词，再丢掉首尾是虚词的组合），
所以「失恋」「奶茶」「电话」这类会反复出现的词能留下，切歪的长块不会污染检索。
自动关键词只当检索坐标，不会出现在模糊化后的正文里（正文只留短标题）。

## 3.5 记忆作用域：私聊 / 群聊互不相通

同一个人在不同场合本来就有两套记忆。这里把它做成硬约束：

| | `scope=private` | `scope=group` |
|---|---|---|
| 来源 | `private:<QQ>` 的会话 | `group:<群号>` 的会话 |
| 谁能看到 | 只有私聊里 | 只有群聊里 |
| 注入 | 私聊的模糊视图只含私聊条目 | 群聊的只含群聊条目 |
| 关键词检索 | 只匹配私聊条目 | 只匹配群聊条目 |
| `diary_list` / `diary_moods` / `diary_recall` | 默认只看自己这一侧 | 同左 |
| `diary_open` / 所有改动 | 打开/改别侧的条目会被拒绝 | 同左 |
| 凌晨结算 | 各生成一份清单，只在自己那一侧展示 | 同左 |

写日记（每天 23:30 的两份文件）是**唯一**两边会合的地方——那是她自己的本子，
两边的素材都会写进去（见 `JOURNAL.md`）。除此之外，两边不共享任何记忆。

旧数据没有 `scope` 字段的一律按 `group` 处理（历史上绝大多数条目来自群聊，
且这个默认不会把私聊内容泄进群）。

## 4. 十二个工具

| # | 工具 | 作用 |
|---|---|---|
| 1 | `diary_write` | 写一条：正文必填，心情 / 没敢说的话可选，档位自定，`scope` 跟当前会话一致 |
| 2 | `diary_list` | 目录：日期、档位、剩几天、心情、短标题；不含正文（只看自己这一侧） |
| 3 | `diary_open` | 展开看全文；**打开不续命**，到期模糊的只给关键词印象；别侧的会拒绝 |
| 4 | `diary_extend` | 延长（+3/+7/+30）；同一天一次；对模糊临存的条目 = 恢复原文并续命 |
| 5 | `diary_promote` | 升一档，寿命按新档位重算 |
| 6 | `diary_demote` | 降一档，寿命按新档位重算 |
| 7 | `diary_shelve` | 搁着：`afraid` 冻结计时 / `uninterested` 照常衰减；理由可改 |
| 8 | `diary_unshelve` | 拿出来；冻结时长在此结算 |
| 9 | `diary_fade` | 记糊：改写正文，原文进 `history` 留底 |
| 10 | `diary_delete` | 划掉（软删除），进回收站 |
| 11 | `diary_amend` | 补写 / 改掉心情、没敢说的话、关键词 |
| 12 | `diary_moods` | 按天数翻**心情**（不含正文，只看自己这一侧） |

外加第十三个（上下文压缩配套，不属于日记本体）：

| 13 | `diary_recall` | 查她**主动打开过**的记录缓存：最多 300 条，一次最多 16 条（按作用域分开） |

刻意不提供的便利：没有「全部展开」、没有批量延长、没有一键恢复全部。
后悔得一条一条来，跟人一样。

## 5. 搁着

| 理由 | 寿命 | 语义 |
|---|---|---|
| `afraid`（不敢看） | **冻结**，不扣 | 躲着的事最不应该忘 |
| `uninterested`（没兴趣） | 照常扣 | 本来就没那么重 |

- 冻结用 `frozenMs` 累积：搁着期间 `expiryAt` 自动顺延；从 `afraid` 改成 `uninterested` 时，
  已冻结的时长一次性结算掉（`frozenMs += now - shelved.at`），之后时间重新开始走。
- 理由随时可改，选错了不算错（再调一次 `diary_shelve` 即覆盖）。
- 搁着的条目**不参与**每轮模糊视图，但结算清单里仍然如实报告（它是事实）。

## 6. 回收站

划掉**不删数据**，只标 `deletedAt`。所有注入、`diary_list` 默认、`diary_moods` 都过滤它；
`diary_list({ includeDeleted: true })` 能看到回收站里的东西——方便回看"她丢掉的是什么"。

## 7. 到期：先模糊化，再给一次机会

到期不是直接删除：

1. 剩余 = 0 → 标 `faded`，原文不再给出（`diary_open` 只返回关键词印象），临存 `fadeGraceDays`（默认 3）天。
2. 临存期间三种选择：
   - **恢复**：`diary_extend`（等于救回来 + 续命），原文立即恢复；
   - **删除**：`diary_delete` 进回收站；
   - **不管**：临存结束自动进回收站（数据仍在，只是不再出现）。

## 8. 凌晨结算清单

`settleHour`（默认 4 点）之后每天第一次运行，结果写进 `settle.pending`，
在**下一轮对话开头**给她看一次，然后标记已送达（不主动往群里发消息）。

**只报事实，不加「你该看看了」的引导**：

```
【日记结算】10月22日
【刻骨铭心】共 2 条，最近一条 还剩 76 天。这些是你最沉重也最幸福的内容；要不要看、要不要留，由你决定。
【快到期的日记】
- 10月17日 重要 还剩 2 天　id=d5
【达到升档条件】
- 普通 已存 16 天，可升到 重要　id=d8
【达到降档条件】
- 刻骨铭心 还剩 20 天，可降到 重要　id=d3
【已到期·模糊临存】
- 10月8日 普通 原文已模糊，临存 2 天　id=d12
  到期处理：延长(diary_extend)可恢复原文并续命；划掉(diary_delete)进回收站；什么都不做则临存结束后自动进回收站。
【画像·可入日记】
- 「害怕被丢下」强度 92：她从不主动说再见（记哪一档由你自己定）　id=portrait:害怕被丢下
```

频率控制：到期提醒用 `warnedAt`（普通 1 天 / 重要 3 天 / 刻骨铭心 7 天）；
升/降档提示 `hintCooldownDays`（默认 3 天）；刻骨铭心长提示 `heartRemindEveryDays`（默认 7 天）。
同一个画像只提示一次。

## 9. 上下文缓存（300 / 16）

- **什么进缓存**：只有她真的调过 `diary_open` 打开看过的条目（"需要她主动打开看的"）。
- **容量**：300 条 FIFO，同一条重复打开只更新时间并挪到末尾。
- **查询**：`diary_recall` 默认 8 条、上限 16 条，可以按词 / 按天数筛。
- 日记、画像、日程是底子；这份缓存是短期记忆，配合压缩上下文用，避免换新窗口。

## 10. 画像联动

本机暂未安装画像插件，所以联动走**文件接口**（`config.json` 的 `diary.portraitFile`）：

```json
{
  "portraits": [
    { "name": "害怕被丢下", "strength": 92, "summary": "她从不主动说再见" }
  ]
}
```

- 也接受顶层直接是数组；缺文件/读坏 = 静默跳过，不打断结算。
- 强度 ≥ `portraitThreshold`（默认 80）才在结算里提示「可以考虑记进日记」，**记哪一档她自己定**。
- 写日记时可以带 `portrait` 字段，把这条和画像对上名字。

## 11. 配置

```json
"diary": {
  "enabled": true,
  "file": "",
  "portraitFile": "",
  "settleHour": 4,
  "fadeGraceDays": 3,
  "heartRemindEveryDays": 7,
  "hintCooldownDays": 3,
  "injectMaxEntries": 10,
  "injectMaxChars": 1200,
  "portraitThreshold": 80
}
```

`enabled: false` = 不注入、不结算（工具仍可用，只是没人提醒她）。
`file` 留空 = `state/diary.json`；相对路径按仓库根解析。

## 15. 面板插件（`plugins/dsh-diary`）

把日记搬进 **DSH 设置页**：概览 / 公开日记 / 私密日记 / 记忆 / 搜索 / 备份。
它**不写内容**——日记由 23:30 的专用会话写、记忆由 13 个工具写；面板是人看和修的那扇窗。

写盘内核移植自 [S3K926/dsh-memory-board](https://github.com/S3K926/dsh-memory-board)（MIT）：

```
指纹拒写 → 幂等跳过 → 内存里先校验 → 改前备份 → 写前再核一次指纹（TOCTOU）
→ 临时文件 + rename → 写完读回复核 → 复核不过就把备份放回去
```

- **指纹** = 内容 sha256 前 32 位。面板打开文章时拿到指纹，保存时回传；这期间桥接写过 → 拒写并提示刷新。
- **改前备份**落在 `state/diary-backups/`，插件不自动删。
- 老规矩：面板不能新建/删除日记、不能改记忆正文——那会破坏「会变糊、会遗忘」这条线。

安装：`node scripts/install-diary-plugin.mjs desktop`（幂等、写前备份），然后**完全退出 DSH 再打开**。
自检：`node plugins/dsh-diary/index.js --selftest`（23 项，不碰真实日记）。

## 16. 几个设计取舍

- **结算靠注入而不是凌晨主动发消息**：凌晨往群里发"你的日记快到期了"既不自然也没人看；
  做成"下一轮对话开头的一小块清单"更符合人回想事情的方式。
- **到期进回收站而不是删除**：项目原则是划掉不删数据；自动到期也一样，只是标记，
  所以 `diary_list({includeDeleted:true})` 永远能翻到"丢掉的是什么"。
- **冻结用时间戳补偿而不是改闹钟**：不维护任何定时任务，`expiryAt` 每次现算，
  重启、改系统时间、跨时区都不会让寿命错乱。
- **文件锁 + 原子写**：桥接进程（注入/结算）和 MCP 进程（工具）同时写同一份 `diary.json`，
  靠 `diary.json.lock`（mtime 10s 超时接管）串行化；读坏文件时**抛错而不是回空**，
  避免一次读失败把整本日记覆盖成空。
- **面板用指纹而不是文件锁**：面板是人手操作，抢锁会让桥接卡住；
  用"读到的指纹"做乐观并发，冲突时拒写并让人刷新——这比锁更符合"人在看"的节奏。
