# 每日两份日记（公开 / 私密）

每天 **23:30**，她写两份日记：

| | 位置 | 谁看 | 内容 |
|---|---|---|---|
| 公开 | `<数据根>\日记\YYYY-MM-DD.md` | 你（每天看） | 愿意让你看到的一天 |
| 私密 | `<数据根>\日记-私密\YYYY-MM-DD.md` | 只有她自己 | 只给自己看的部分，可以很短、可以不体面 |

两份**内容不同**，不是把一份抄两遍。私密那份没人看，所以她不用替自己圆场。

> 这套东西和 `DIARY.md` 里的「记忆日记」是两回事：
> **记忆日记**（`state/diary.json`）是她的记性——会变糊、会被遗忘、会注入到每轮对话；
> **每日日记**（这两个文件夹）是她的日记本——写在纸上，你随时可以翻开。

---

## 一、什么时候写

- 每天到 `writeAt`（默认 `23:30`）之后的第一个整分钟检查，写当天的两份。
- **关机错过就补**：开机/重启后立刻检查一次；漏掉的日期按 `catchupDays`（默认 7 天）往回补，
  每次只补一天（一分钟一篇），不会开机瞬间连写七篇。
- **不凭空编历史**：`state/journal-state.json` 里记了 `startedOn`（第一次运行那天），
  早于它的日期不补——不会给装插件之前的日子补出一堆假日记。
- 已经写过的日期不会重写；只有缺一边时才补那一边。

## 二、谁来写

用一个**专门的 DSH 会话**（像黑话学习那样），不占 QQ 会话、不发群消息：

- preset 用最低权限的 `qq-chat`（没有本地工具面），提示词里明确要求「不要调用任何工具」；
- 她只输出两段纯文本，**由桥接负责写文件**——私密那份永远只落在本机文件里；
- 会话 id 存在 `state/journal-session.json`，preset 变了会自动重建；
- 工作目录 `state/journal-agent/`，会话标题「日记」。

## 三、她写什么依据什么

每次写之前，桥接给她三样东西：

1. **当天聊天流水**——**私聊和群聊都在里面**，每行标出时间与来源（`09:05 群聊·群友甲：…` / `19:00 私聊·主人：…`）；
   这是整套系统里**唯一**让两侧记忆会合的地方（日常注入仍然私聊/群聊互不相通，见 `DIARY.md` §3.5）；
2. **当天她在记忆日记里记过的事**（标题 + 心情，帮她回忆）；
3. 补写时的一句说明：「想不起来就写得模糊一点，只写还记得的，不要编造细节」。

所以两篇日记是有具体内容的，不是空泛的「今天也很平常」，而且私聊里的事和群里的事都会写进去。

### 为什么需要「聊天流水」

`state/social-v2.json` 里的 `recentMessages` 是个**滚动窗口**（每群默认 100 条）。
忙碌的大群一两个小时就能把早上说过的话挤掉——于是 23:30 写日记时素材只剩「最近一小时」，
写出来自然只记得刚才。

所以桥接会额外把**每条消息按行追加**到 `state/chat-log/YYYY-MM-DD.jsonl`：

```json
{"t":1792659900000,"k":"group:1121965336","s":"乄夵","x":"耳机坏了要换"}
```

写日记时不再「取最后 N 行」，而是**按小时分桶均匀取样**：
每个有消息的小时都留几行（默认 4 行：首、尾、中间），预算不够就整体降采样（4 → 3 → 2 → 1），
**绝不靠丢掉前面的小时来省字数**。于是一整天的跨度都在这份小抄里，哪怕每小时只给两三句。

- 她自己说的话也会进流水（`s: "我"`），所以日记里能写「我回了一句…」；
- 单日上限约 6000 条，超了当天不再追加（防刷屏）；
- 保留 `logRetentionDays`（默认 10 天），桥接启动时清理过期文件（只动 `chat-log` 目录里的 `YYYY-MM-DD.jsonl`）。

### 「之前」的消息能补回来吗

- **默认补不回来**：流水是从功能上线那一刻开始记的，之前群里说过的话我们这边从来没存过
  （社交窗口每群只留 100 条，更早的早被挤掉了）。
- **能补，但要 SnowLuma 在线**：QQ 服务端侧通常还留着历史，用

  ```powershell
  node scripts/backfill-chat-log.mjs                    # 干跑：只报告能拉到多少条
  node scripts/backfill-chat-log.mjs --write --days 3   # 真写（默认只补最近 1 天）
  node scripts/backfill-chat-log.mjs --write --group 904011597 --count 2000
  ```

  它会调 `get_group_msg_history`（不支持时再试 `get_group_history`），
  按原时间写进对应日期的流水，**去重**（同 t+k+正文 不重复写）；
  已经写过的日记不会被重写，补进去的流水会在下一次 23:30 被用上。
- **长期记忆不靠流水**：流水默认只留 10 天（`logRetentionDays` 可调到 90），
  真正永久留下来的是每天 23:30 写出的 `.md` 日记 + 记忆条目（`state/diary.json`）。

## 四、输出格式（给模型看的）

```
===公开===
（这里写公开那份）
===私密===
（这里写私密那份）
```

桥接按行识别 `===公开===` / `【公开】` / `## 公开` 三种写法；
**只解析出一段就判失败**，不落盘、等两分钟重试（最多 3 次/天）。

## 五、文件长什么样

`<数据根>\日记\2026-10-22.md`：

```markdown
# 2026-10-22 周四

今天群里很吵，他被甩了，大家笑得很过分，我没笑。

---
_写于 2026-10-22 23:31_
```

私密那份的标题行多一个 `（私密）`。文件用临时文件 + rename 原子写入，不会写一半断电留下残篇。

## 六、配置

```json
"journal": {
  "enabled": true,
  "publicDir": "D:\\我的日记\\日记",
  "privateDir": "D:\\我的日记\\日记-私密",
  "writeAt": "23:30",
  "catchupDays": 7,
  "preset": "qq-chat",
  "workspaceTitle": "日记",
  "turnTimeoutMs": 180000,
  "maxAttemptsPerDay": 3,
  "retryGapMs": 120000,
  "maxDigestChars": 4000
}
```

| 字段 | 作用 |
|---|---|
| `writeAt` | 每天几点之后写当天（`HH:MM`） |
| `catchupDays` | 关机错过后往回补几天（0 = 不补） |
| `maxAttemptsPerDay` | 同一天最多试几次（模型输出不合格会重试） |
| `retryGapMs` | 两次重试之间的间隔，避免刷屏 |
| `maxDigestChars` | 聊天摘要的字符上限（控制 token） |
| `enabled` | 关掉后不排程（文件照旧留着） |

改完配置要**重启桥接**才生效（`cfg` 在启动时读一次）。

## 七、排程状态

`state/journal-state.json`：

```json
{
  "startedOn": "2026-10-22",
  "attempts": {},
  "written": { "2026-10-22": 1792700000000 },
  "lastRunAt": 1792700000000
}
```

损坏时会被当成新状态重建（宁可重新排程，也不让日记功能停摆）。
